### 3.2 修复 `buildFontStack` family name 解析错误

**问题**：v0.2 写的代码有个隐藏 bug——`buildFontStack(primaryFamily, ...)` 期望入参是单一 family（如 `"Inter"`），但 renderer.ts 实际传的是**完整 font-stack 字符串**（如 `'"Inter", "Source Han Sans SC", sans-serif'`）。

`buildFontStack` 又把这个完整字符串用引号包起来当 family name 查找，结果整个 stack 变成一个不存在的 family name，**永远 fallback 到 sans-serif 默认字体**。

**修复**：`buildFontStack` 内部先调 `normalizeFontFamily()` 切出第一项再包引号，健壮性也更好（直接传单一 family 名也能用）。

```ts
export function buildFontStack(familyOrStack: string, fontSizePx: number, style: string): string {
  const primaryFamily = normalizeFontFamily(familyOrStack);  // ← 新增：先规范化
  const styleStr = style ? `${style} ` : '';
  const primary = `"${primaryFamily}"`;
  // ... 拼 CJK fallback
}
```

### 3.3 关闭系统字体注册

**问题**：v0.2 末尾的"双保险"方案——同时注册系统字体（`msyh.ttc` / `simhei.ttf` / `simsun.ttc`）和思源黑体。但实测发现，`@napi-rs/canvas` 在 Windows 上同时注册多个 CJK 字体会让 `Source Han Sans SC` 的 family 查找返回错误结果（疑似 collection font 的 type index 冲突）。

**修复**：`registerAllFonts()` 现在只调 `registerCustomFonts()`，系统字体注册代码保留但注释掉，留作将来非 Win/macOS 平台兜底用。**打包字体就够用了**，不再需要系统兜底。

```ts
export function registerAllFonts(): void {
  registerCustomFonts();
  // 系统字体暂不注册（@napi-rs/canvas 多字体注册有冲突，会让 Source Han Sans SC 失效）
  // registerSystemFonts();
}
```

### 3.4 字体下载脚本

| 脚本 | 用途 | 来源 |
|------|------|------|
| `download-fonts.js` | 思源黑体 Regular + Bold | jsDelivr CDN（`@adobe-fonts/source-han-sans@release`） |
| `download-inter.js` | Inter Regular + Bold | jsDelivr CDN（`@fontsource/inter`）的 woff2 → wawoff2 转 ttf |

两个脚本都有：
- 多源 fallback（jsDelivr → unpkg → raw.githubusercontent.com）
- 已有文件大小 > 50KB 时自动跳过
- 文件太小时自动重下

**为什么不用 Inter 的 OTF？** rsms/inter v4 之后仓库里只放 woff/woff2，不再提供 OTF/TTF 直接下载。Inter 的拉丁子集只有 21KB woff2，转成 ttf 也就 60KB，对体积完全无感。

## 六、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 字体打包位置 | `server/fonts/` 而非 `web/public/fonts/` | 后端渲染才是字体真正使用的地方；web 端 Konva 走浏览器 fallback，不依赖打包字体 |
| 注册名 vs 文件名 | 按文件名 pattern 映射成 `Inter` / `Source Han Sans SC` 等固定 family | 模板里硬编码的 family 名是稳定的，文件名可以自由更换 |
| 系统字体注册 | 默认关闭 | 实测与思源黑体冲突；打包字体已经足够 |
| `buildFontStack` 入参 | 接受完整 font-stack 字符串，内部 normalize | 健壮性更好，调用方不用关心是否已 normalize |
| 字体下载策略 | 脚本化（不写死 npm 安装） | 字体是设计资产不是依赖；脚本可重跑、可被 CI 用；Git 不必 commit 32MB |
| Inter 字体格式 | 下载 woff2 后转 ttf | rsms/inter 不再提供 OTF/TTF；woff2 → ttf 用 wawoff2 一行 API 搞定 |
| 模板 fontFamily 写法 | primary = Inter，fallback = Source Han Sans SC | 主要内容是英文+数字（模特卡片场景），但中英双语 labels 也常见 |

## 八、调试经验沉淀

### 8.1 PowerShell `Invoke-RestMethod` 的 UTF-8 陷阱

调试过程中浪费了 30 分钟定位的"假 bug"——PowerShell 5.1 的 `Invoke-RestMethod -Body $json` 默认按**系统 ANSI (GBK) 编码**发送请求体，导致 UTF-8 中文 body 字节流被破坏，server 收到 `content: "????"`。

**现象**：fontFamily 字段（ASCII）正常，content 字段（中文）变 "????"——非常像"字体注册失败导致 tofu"的症状。

**诊断**：
```js
// 在 renderer.ts 加一行 log：
appendFileSync('font-debug.log', `drawText content="${el.content}"`);
```
发现 `content` 已经是 `????`，证明 HTTP 传输阶段就坏了，不是字体问题。

**绕开方案**：
- 测试用 `node scripts/test-render.js`（Node.js 原生 `http` 模块 + `Buffer.byteLength`）发请求
- 不再用 `Invoke-RestMethod` 测中文

**已记入 user.md**，避免下次再踩。

### 8.2 @napi-rs/canvas 的字体 fallback 行为

实测发现 `@napi-rs/canvas` 的字符级 fallback **比浏览器差**——浏览器自动按字符找 fallback，canvas 只按"第一个 family 里有没有这个字符"决定：

- ✅ `ctx.font = '64px "Inter", "Source Han Sans SC"'` 对"林若汐 165cm" 渲染时：Inter 缺"林/若/汐"，自动 fallback 到 Source Han Sans SC
- ❌ `ctx.font = '64px "Source Han Sans SC", "Inter"'` 对"林若汐 165cm"：Source Han Sans SC 全部有，但英文也会用它（不漂亮）

所以**font-stack 顺序很关键**——**英文/数字为主的文本要把 Inter 放前面，CJK 为主的文本要把 Source Han Sans SC 放前面**。模板里大部分"身高 height"这种 label 都是英文+中文混合，按"英文优先"放 Inter 在前最合理。

### 8.3 msyh.ttc collection font 干扰

`C:\Windows\Fonts\msyh.ttc` 是 TrueType Collection（一个文件里包含 Regular/Bold/Light 多个字体）。`@napi-rs/canvas` 把它当一个 family 注册，但 collection 的 type index 跟其他 family 在同一个 canvas 进程里**会冲突**——表现就是 `Source Han Sans SC` 的 family 查找返回不存在的 type。

**结论**：在 Win 上同时注册 msyh.ttc + 思源黑体 = 不可靠。要么只用 msyh.ttc，要么只用思源黑体。打包字体方案选了后者。

## 九、待优化 / 已知限制

1. **字体体积大**：思源黑体 32 MB，clone 项目或下载 ZIP 会比较慢。后续考虑：
   - 用 `fontmin` 之类的工具剪裁掉没用到的字符（如只保留 GB2312 字符集 → 减到 8 MB 左右）
   - 或者改用 `fontsource-noto-sans-sc` 的子集拆分
2. **Inter 缺中文字符**：Inter 拉丁子集只覆盖 ASCII/扩展拉丁，遇到 CJK 字符需 fallback。如果用户输入冷门中文字符（如某些生僻字），需依赖 Source Han Sans SC 的字符覆盖
3. **下载脚本依赖网络**：首次 clone 项目后必须能连 jsDelivr 才能下字体。如果用户完全离线，需要另想办法（如 commit 字体到 Git LFS，或随安装包打包）
4. **字体未做 subset**：思源黑体全字符集（68000+ 字），但模型卡片场景只会用到 GB2312 一二级 + 常用符号。subset 后可减到 5-8 MB
5. **历史记录粒度未优化**：v0.2 提的问题还在，每次保存整个 elements 数组
