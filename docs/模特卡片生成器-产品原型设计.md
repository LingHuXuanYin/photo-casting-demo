# 模特卡片生成器 (Model Card Generator) - 产品原型设计

> 版本：v0.3（已对齐关键决策：模特本人 / 本地部署 / 无账号 / 思源黑体）
> 作者：Mavis
> 适用：Web 端（响应式桌面优先）

---

## 一、产品概述

| 项目 | 内容 |
|------|------|
| 产品名 | 模特卡片生成器（Model Card Generator） |
| 产品类型 | SaaS / 在线工具 |
| 目标用户 | **模特本人为主**（v1），经纪人/摄影师为辅（v2 考虑） |
| 核心价值 | 模特上传自己的照片和身材数据，挑个模板，一键导出属于自己的模卡 |
| 关键差异化 | 行业模板预设 + 自由画布 + 高清后端渲染 |
| 导出格式 | JPG / PDF |
| 后端渲染 | **node-canvas**（性能优，schema 与前端同构） |
| 画布尺寸 | **支持自定义**（预设 A4 竖版/横版、1:1、3:4 等常用比例） |

### 核心用户故事

1. 作为**模特**，我刚拍完一组写真，想自己做一张模卡，发到社交平台、投递给经纪公司。
2. 作为**模特**，我的身高三围变了，想更新一下模卡，所有尺寸/比例/信息都是我自己控制。
3. 作为**模特**，我想换不同风格的模卡投递不同平台（时尚/商业/童模），模板能一键切换。

## 二、整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    前端 (Web SPA)                        │
│  ┌──────────┐   ┌──────────┐   ┌────────────────────┐  │
│  │ 项目管理 │──▶│ 画布编辑 │──▶│  预览 / 导出请求   │  │
│  └──────────┘   └──────────┘   └────────┬───────────┘  │
│                                          │ 布局 JSON     │
└──────────────────────────────────────────┼──────────────┘
                                           ▼
┌─────────────────────────────────────────────────────────┐
│                    后端服务                              │
│  ┌──────────┐   ┌──────────┐   ┌────────────────────┐  │
│  │ 草稿存储 │   │ 模板管理 │   │ 渲染服务 (Node)     │  │
│  │ (DB)     │   │          │   │ node-canvas + pdf-lib│  │
│  └──────────┘   └──────────┘   └────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

**数据流关键点**：前端编辑器把画布上的所有元素（图片/文字/位置/尺寸/层级）序列化成一份 JSON 草稿，草稿既能存到数据库供下次编辑，也能直接 POST 给后端渲染服务生成最终高清图。**前后端共用同一份 schema**，降低维护成本。

## 三、页面清单与流程

### 主流程

```
项目列表 → 新建项目（上传照片）→ 录入模特信息 → 选择模板 → 画布微调 → 预览 → 导出
   │                                                                 │
   └──────────────── 历史项目 / 重新编辑 ────────────────────────────┘
```

### 页面清单（共计 7 个核心页 + 3 个弹层）

| # | 页面 | 优先级 | 说明 |
|---|------|--------|------|
| 1 | 项目列表 (Dashboard) | P0 | 所有模卡项目的入口 |
| 2 | 新建项目 - 照片上传 | P0 | 多图上传 + 智能分类 |
| 3 | 新建项目 - 模特信息 | P0 | 录入模特基础信息（针对模特本人优化） |
| 4 | 模板选择 | P0 | 行业预设模板，含自定义尺寸 |
| 5 | 画布编辑器 | **P0 核心** | 拖拽、缩放、对齐、尺寸自定义 |
| 6 | 预览与导出 | P0 | JPG / PDF 导出 |
| 7 | 历史记录 | P1 | 渲染历史与下载 |
| - | 弹层：照片裁剪 | P1 | 单张照片裁剪 |
| - | 弹层：模特信息字段配置 | P2 | 自定义字段 |
| - | 弹层：协作分享 | P2 | 链接分享给经纪人 |

#### 关键交互细节

1. **拖拽**：鼠标按住元素即可移动，松开时自动吸附到最近的栅格点（8pt 栅格）
2. **缩放**：拖拽元素角点，按住 Shift 保持比例
3. **多选**：框选 / Shift+点击；选中后可批量移动/对齐
4. **对齐辅助线**：拖拽时显示与其他元素边缘/中心对齐的虚线
5. **键盘快捷键**：
   - `Ctrl/Cmd + Z` 撤销
   - `Ctrl/Cmd + Shift + Z` 重做
   - `Delete` 删除选中
   - `Ctrl/Cmd + D` 复制
   - `方向键` 微调（1pt，按 Shift 为 10pt）
   - `Ctrl/Cmd + S` 保存草稿
6. **自动保存**：每 30 秒自动保存草稿到后端

## 五、关键设计决策与理由

| 决策 | 选择 | 理由 |
|------|------|------|
| 用户对象 | 模特本人为主 | 模特自己上传、自己编辑、自己下载，闭环最短 |
| 账号体系 | **不做** | v1 极简，模特数据全存浏览器本地 IndexedDB |
| 部署形态 | **本地单机** | 一台机器跑前端 + 后端，零云依赖 |
| 画布坐标系 | 绝对坐标（pt） | 印刷行业标准单位，与 node-canvas 1:1 对齐 |
| 画布尺寸 | 自定义 + 预设 | 不同平台投递需要不同比例（IG 1:1、抖音 9:16、印刷 A4） |
| 图片存储 | **前端 base64 直接传给后端** | 本地场景无需 CDN/OSS，最简 |
| 草稿存储 | **浏览器 IndexedDB** | 不用数据库，刷新不丢、关浏览器不丢 |
| 后端渲染 | **node-canvas** | 性能好、与前端 schema 概念一致、PDF 嵌入可控 |
| PDF 生成 | node-canvas 出图 + pdf-lib 包装 | node-canvas 直接出 PDF 不优雅；出图后用 pdf-lib 嵌入最稳 |
| 字体 | **思源黑体 + Inter**（免费可商用） | 无授权风险，覆盖中英文 |
| 导出分辨率 | 1x/2x（v1），4x 印刷（v2） | 1x 屏幕够用，2x 满足朋友圈/小红书高清，4x CMYK 印刷是 v2 |
| 模板系统 | JSON 模板（同画布结构） | 用户改完模板可直接保存为"我的模板" |
| 队列 | **不需要** | 同步渲染 3-10 秒可接受，v1 单机无并发压力 |
| 协作 | v1 单人，v2 加分享链接 | 优先核心闭环，协作是增量需求 |

### 前端

| 项目 | 选型 | 理由 |
|------|------|------|
| 框架 | React + TypeScript | 生态成熟，类型安全 |

### 后端（v1 本地部署极简版）

| 项目 | 选型 | 理由 |
|------|------|------|
| 语言 | Node.js + TypeScript | 与前端共享类型 |
| 框架 | Fastify | 轻量、性能好、TypeScript 友好 |
| 渲染 | **node-canvas** | 性能优，schema 概念与前端一致 |
| PDF | **pdf-lib** | 把 JPG 嵌入 PDF，体积小、API 友好 |
| 图片处理 | sharp | 缩略图、压缩、格式转换 |
| 字体注册 | node-canvas registerFont | **思源黑体（Source Han Sans）+ Inter**（均免费可商用） |
| 存储 | **无需 DB**，草稿存浏览器 IndexedDB；图片前端 base64 / Blob 传给后端 | 本地单机，简化部署 |
| 队列 | **不需要**，渲染同步返回（v1 流量小） | 3-10 秒内可同步等 |

### 渲染流程（v1，本地极简版）

```
前端 POST /api/cards/render
  ↓
  body: { canvas, elements, model, format: "jpg" | "pdf", scale: 1 | 2 }
        (images 已在前端转 base64 直接发，不走 URL)
  ↓
后端:
  1. 把 elements 中的 base64 图片解码到内存 Buffer
  2. 用 sharp 加载图片（或直接用 node-canvas 的 Image.fromBuffer）
  3. 创建 node-canvas（width * scale, height * scale）
  4. 按 zIndex 顺序绘制所有元素（图片 drawImage、文字 fillText）
  5. if format === "jpg": canvas.toBuffer('image/jpeg', { quality: 85|92 })
     if format === "pdf": 出 JPG buffer → 用 pdf-lib 创建 PDF 嵌入
  ↓
后端直接返回二进制流（image/jpeg 或 application/pdf）
  ↓
前端 Blob 接住，触发浏览器下载
```

**为什么这样设计：**
- 没有 OSS/URL 中转，前后端交互最简单
- base64 体积大约 +33%，但本地场景 1-5 张图没问题；超过 10 张再做优化
- 同步返回：v1 单机本地用，没必要搞异步队列
- 日后想上云：把 `返回二进制` 换成 `上传到 OSS 返回 URL` 就好，接口契约不变
