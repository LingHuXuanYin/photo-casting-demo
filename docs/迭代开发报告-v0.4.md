#### 3.2.3 缩略图自动生成

`ExportModal` 导出成功后自动调用 1x 渲染存缩略图：

```ts
// ExportModal 导出成功分支
const generateThumbnail = async () => {
  await saveNow(); // 先把最新状态写盘
  const thumbnail = await renderCanvasToThumbnail(); // 1x 渲染拿小图
  if (!thumbnail) return;
  await saveProject({ ..., thumbnail, ... });
  saveCurrentProjectId(projectId);
};
```

- 缩略图 jpeg quality=70（控制大小）
- 直接用 1x 渲染的图（避免前端用 Konva 重新画一遍）
- 写到 `project.thumbnail` 字段，下次 Dashboard 加载时显示

## 六、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 测试覆盖 | 后端 API 集成 + 前端 store 单元（不做 E2E 浏览器测试） | 本地单机 MVP；端到端用冒烟测试足够；Playwright 太重 |
| view state | 简单 `useState<'dashboard' \| 'editor'>`，不引入 router | 2 个页面够用，引入 react-router 过度设计 |
| 默认 view | 启动时自动决定（有项目 → editor，无 → dashboard） | 老用户回到工作状态，新用户看到引导页 |
| 缩略图存哪 | project.thumbnail (IndexedDB)，不是文件系统 | 本地单机 + 零依赖，all-in-IDB 统一管理 |
| 缩略图生成时机 | 导出成功后异步存（不阻塞用户操作） | 用户体验优先；存失败也不影响导出结果 |
| 缩略图生成方式 | 复用 server 1x 渲染（不画 Konva） | 缩略图和最终导出视觉一致；省前端开发量 |
| 项目卡片来源 | IndexedDB 列表，按 updatedAt 倒序 | 已经在 db.ts 实现好；零成本 |
| 删除确认 | 必弹确认框（不可一键删） | 模特数据无法重建；防止误操作 |
| Dashboard 不做的 | 复制项目 / 历史版本 / 标签 / 分类 | v1 极简；用户反馈后再加 |

## 九、待优化 / 已知限制

1. **缩略图每次都重渲染**：导出后用 server 1x 重新画一次存缩略图（多一次 HTTP）。后续可用 Konva stage 直接 `toDataURL` 客户端画，更快
2. **Dashboard 不显示项目状态标签**：设计稿有"草稿/渲染中/已生成"标签，但 v1 没持久化 status 字段，先不做
3. **没有复制项目功能**：用户多次复用模板时需要"基于此项目新建"。v2 加
4. **没有历史版本**：undo/redo 内存里，刷新后丢失。IndexedDB 只存当前快照。v2 可加版本历史
5. **Dashboard 列表没有分页**：项目数 > 50 时一次性全渲染会卡。先按"普通用户最多 20 个项目"假设，不分页
6. **缩略图大小不控制**：quality=70 但画布 4000×4000 还是会很大（~200KB）。后续可用 canvas resize 压缩到固定 400px 宽
7. **没有按模特搜索时高亮匹配项**：搜出结果后只过滤，不标红匹配位置
8. **点 Dashboard 卡片时直接进 editor，没有"预览"选项**：v1 极简，先这样
