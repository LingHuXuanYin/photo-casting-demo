## 五、关键 Bug 修复

### Bug #1：图片缩放失效 + 蓝色外框

**症状**
- 添加图片后，无法通过角点调整大小
- 选中图片时，画布上有个蓝色实心边框（用户不喜欢）

**根因**
- 把 `KImage` 包在 `Group` 里作为 Konva 节点
- Group 没显式设 `width/height`，Transformer 读不到尺寸
- `handleTransformEnd` 中 `node.width() * scaleX` = 0，兜底成 MIN_SIZE = 20pt
- 另外为了"选中提示"加的蓝色 Rect，图片上加看起来很丑

**修复**
- 去掉 Group 包装，id 和事件直接挂到 `KImage`
- 选中视觉统一交给 Transformer（`borderDash` 虚线边框）
- 文字也一样去掉 Group

**文件**：`web/src/canvas/CanvasStage.tsx`

### Bug #2：拖拽位置跳变

**症状**
- 拖拽图片到某位置后松开，图片"跳"到错误位置
- 缩放/旋转后位置也错位

**根因**
- Konva 的 `node.x()` 返回的是 **未缩放画布坐标**（Stage 的 scale 不影响子节点位置，只影响显示）
- 我误以为需要把缩放还原，多除了一次 `safeScale`
- 结果保存的位置比实际拖到的小 1/safeScale 倍

**修复**
- 删除 `handleDragEnd` / `handleDragMove` / `handleTransformEnd` 三处的 `/ safeScale`
- 保留 `strokeWidth={1 / safeScale}` 和 `dash={4 / safeScale}`（这两个是故意除的，让辅助线在缩放后视觉粗细不变）

**文件**：`web/src/canvas/CanvasStage.tsx`

## 六、技术决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 前端框架 | React 18 + TS | 生态成熟，react-konva 18 兼容 |
| 画布库 | Konva 9 + react-konva 18 | 性能好，与 node-canvas 概念对应；避开 19.x 对 React 19 的依赖 |
| 状态管理 | Zustand 4 | 比 Redux 简单，比 Context 性能好，对 TS 友好 |
| 包管理 | npm workspaces | Windows 兼容最好，避免 pnpm 装问题 |
| 渲染并发 | concurrently | 根目录一键起前后端 |
| 元素 ID 生成 | crypto.randomUUID | 浏览器原生，无依赖 |
| 拖拽系统 | Konva 内置 drag | 不用 react-dnd 之类的库 |
| 旋转/缩放 | Konva Transformer | 8 个角点 + 旋转手柄，Konva 原生支持 |
| 缩放适配 | Stage scale + 居中偏移 | 画布按比例显示在容器中央，留 padding |

## 八、已知的边界情况 / 待优化

1. **历史记录粒度**：当前是全量快照，每步保存整个 elements 数组。10 步后就保存 10 倍数据。后续可改成"基于 patch 的差分历史"省内存
2. **文字高度**：当前 `el.h` 是创建时的初始高度，文字内容变化时高度不自动调整（依赖 visualHeight 兜底）
3. **大图片性能**：base64 + Konva.Image，图片 > 5MB 时拖拽可能卡顿，后续可加缩略图
4. **框选**：还没做，目前只支持 Shift+点击多选
5. **自动保存**：Ctrl+S 已经是占位，P0-3 才接 IndexedDB
6. **图片裁剪**：Properties Panel 的 fit 字段还没实际生效（需要 Konva crop 配合，后续做）
